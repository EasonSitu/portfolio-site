# Three.js 个人网站重建设计规格

## 1. 项目目标

在不修改现有 `portfolio-site` 的前提下，建立一个独立的、以 Three.js
为核心的个人求职网站版本。

新版本需要在浏览器中重新实现已经确认的视觉方向：深色编辑感背景、后置大型
拱门、五层方形悬浮载板、中央能量光柱，以及半透明核心球体。整体要有高级、
有空间感的视觉效果，同时不能牺牲招聘者阅读文字的效率。

Blender / GLB 版本只作为视觉参考。新版本的主要场景不能依赖现有 GLB，
而应使用 Three.js 代码直接生成几何体、材质和灯光。

## 2. 项目隔离与安全边界

- 保留现有项目 `D:\codex\Eason\portfolio-site`，不修改它的运行逻辑。
- 新建独立项目 `D:\codex\Eason\portfolio-site-threejs`。
- 新项目可以复制已确认的事实内容、三语文案和简历 PDF。
- 新项目不得直接引用原项目的运行时组件或 GLB 资产作为主场景。
- 开发期间保留现有网站，作为内容参考和视觉回退版本。

## 3. 目标用户与内容定位

主要用户是香港地区的招聘人员、招聘经理和岗位负责人。

首屏需要传达：司徒智成能够连接业务需求、产品与技术团队，以及真实项目
的实施交付。

网站不应把他包装成资深软件工程师、AI 研究员或底层 IoT 专家，而应突出：

> 能理解问题、梳理需求、协调团队，并把技术方案推进到实际落地。

第一版继续支持三种语言：

- 英文：`en`
- 简体中文：`zh-CN`
- 繁体中文：`zh-HK`

文案采用数据驱动方式管理，避免在组件中重复维护三套内容。

## 4. 视觉构图

### 4.1 Hero 页面布局

- 使用全屏深色背景，并加入克制的网格或噪点氛围。
- 左侧放置姓名、职业定位、简短说明和两个主要操作按钮。
- 右侧放置 Three.js 场景，作为首屏的视觉重点。
- 桌面端必须保留明确的左侧文字安全区，3D 场景不能遮挡标题和按钮。
- 窄屏设备上，场景需要缩小或切换为受控的静态回退图，文字优先保留。

### 4.2 场景对象

使用 Three.js 代码直接生成以下对象：

1. 一个具有真实厚度、略微偏置的后置大型拱门；
2. 五块方形悬浮面板，保持统一设计语言，同时在切角、延伸边和嵌槽位置
   上做小幅、受控的差异；
3. 分层基座 / 核心平台，以及一条简短的能量路径；
4. 位于最底层面板下方的暖色半透明核心球体；
5. 贯穿球体与五层面板的垂直能量光柱；
6. 少量侧面石块或环境体块，用于增加空间深度，但不能抢主体注意力。

五层面板对应的能力 / 交付流程为：

- 业务背景（Business Context）
- 需求梳理（Requirements）
- 协作推进（Coordination）
- 测试验证（Testing）
- 实施交付（Delivery）

标签应贴近各自面板显示，不使用数字前缀，也不能遮挡正在旋转的主体。

## 5. Three.js 技术架构

使用 Next.js 作为页面外壳，在仅限浏览器端运行的 Hero 组件中使用原生
Three.js。新版本不使用 React Three Fiber 来实现这套主场景。

建议的代码边界如下：

```text
pages/index.js
  负责语言状态和页面外壳

components/ThreeHero/ThreeHero.js
  负责浏览器端生命周期和 Canvas 挂载

lib/three-scene/createScene.mjs
  负责场景、相机、渲染器、灯光和后期处理

lib/three-scene/buildGeometry.mjs
  负责拱门、面板、基座、球体和光柱几何体

lib/three-scene/materials.mjs
  负责石材、烟熏玻璃、金属、能量和球体材质

lib/three-scene/interaction.mjs
  负责指针命中检测、悬停、选中和旋转状态

data/heroContent.mjs
  负责三语文案
```

第一版需要使用单一渲染循环，并在组件卸载时释放几何体、材质和事件监听器。

## 6. 材质与灯光方向

- 拱门：深色石材 / 石墨质感，使用低频程序噪声和粗糙度变化；不要出现
  明显重复的砖块纹理。
- 面板：烟熏玻璃或深蓝半透明板材，具有清晰厚度、Clearcoat、克制的蚀刻
  线和暖 / 冷色边缘反光。
- 边框：深色金属，带受控的蓝紫色反射。
- 球体：使用 `MeshPhysicalMaterial`，加入 Transmission / IOR、象牙暖色
  和柔和的内部光感。
- 光柱：暖色高亮核心，加上透明度更低、范围更宽的外层光晕。
- 灯光：暖色主能量光、冷紫色轮廓补光和低强度环境光，并使用克制的 Bloom。

材质复杂度需要受质量等级控制，使桌面端可以使用更丰富的静态效果，移动端
则可以切换到较轻量的版本。

## 7. 交互方式

- 鼠标悬停面板时：面板轻微抬升、旋转几度、边缘变亮，同时激活旁边标签。
- 点击面板时：进入选中状态，并短暂加速该面板的旋转；再次点击可恢复待机状态。
- 指针移动时：只产生轻微的相机 / 场景视差，不做大幅环绕镜头。
- 滚动和导航：第一版只需要可靠的锚点跳转，场景不能阻塞正常页面滚动。
- 当用户启用 `prefers-reduced-motion` 时：关闭旋转和视差，但仍保留场景、标签
  和基本视觉层次。

## 8. 实施阶段

### 阶段一：浏览器静态场景

- 创建独立项目。
- 建立场景几何体和相机。
- 以 16:9 画面匹配现有 Blender 视觉参考。
- 加入截图 / 调试模式，用于快速对比构图。

### 阶段二：材质与灯光

- 加入程序化石材、烟熏玻璃、球体和能量光材质。
- 加入 Bloom 以及暖 / 冷色灯光关系。
- 调整桌面端和移动端质量等级。

### 阶段三：交互

- 加入面板悬停和点击状态。
- 加入标签与当前激活层的说明文字。
- 加入轻微指针视差和减少动画支持。

### 阶段四：内容整合

- 接入英文、简体中文和繁体中文文案。
- 接入简历下载和招聘者主要操作。
- 加入最小化的 About、Experience、Contact 锚点，不虚构新的项目内容。

### 阶段五：验证

- 运行内容和基础功能测试。
- 构建生产版本。
- 验证 1440×1000、1024×768 和 390×844 三种尺寸。
- 检查 WebGL 不可用、减少动画、语言切换和横向溢出等情况。

## 9. 验收标准

新版本进入下一轮视觉调整前，需要满足：

1. 能独立运行，不依赖原项目的运行时和 GLB 主资产；
2. 静态 Hero 清楚呈现“前景精密装置 + 后景石构拱门”的关系；
3. 五层面板可以独立命中、悬停和选中；
4. 桌面端左侧文字始终清晰可读；
5. 三种语言使用同一套内容数据正常切换；
6. 在 WebGL、动画或高质量效果不可用时可以优雅降级；
7. 最终结果仍然是招聘者易于理解的个人网站，而不是脱离内容的 3D 展示。

## 10. 工具说明

用户提到的“5.6 Luna max”目前不是 Codex 当前环境中可以直接选择的运行时
模型名称。这不影响网站架构；实际实现将使用当前可用的本地运行环境，并通过
代码检查和浏览器验证来确认结果。
